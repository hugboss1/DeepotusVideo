You will set an AI provider's key, choose which engine does what, connect a free provider or a server on your network, and protect your keys with a password. Ten minutes, free; keys are created with each provider.

Before you start

An API key is a code the provider gives you on its website, in your account. It lets the app work on your behalf; the provider bills you. Only one is required to start: fal.ai.

Set a key

  1. Open Settings › API keys. Each provider has its row and its status: missing until a key is set. The fal, heygen and voice badges in the header lead here in one click.
  2. Click Guide: it tells where to create the key with the provider and how it is billed.
  3. Paste the key in the field, then Save. It works right away, no restart.
  4. Click Test on the row: the provider says whether it accepts the key, without spending anything.

To set several keys at once, fill in the fields then Save all changes.

Choose the engine for each job

  1. Open Settings › Provider defaults. The image to video, avatar and voiceover rows say which key serves them and whether it is set.
  2. News summarizer and Schedule planner each pick a text engine: a built-in one (Anthropic, OpenAI, Gemini, Ollama), a free provider or a local server. "Automatic" takes the first engine that is ready.
  3. Further down, each configured engine has its Default model row: pick from the list read from the provider, or type a name. Test checks that the model is published, without spending anything; Save applies it at once.

The choice is written to the app's settings file: it applies to every screen. A model name that looks like a key pasted by mistake is refused and flagged in red.

Add a free provider

  1. In API keys, scroll down to Free providers (OpenAI-compatible), then + Add a provider.
  2. Pick a preset (DeepSeek, OpenRouter, Mistral, Groq, Together, xAI) or type a name and an https URL. Paste the key.
  3. Read the list asks the provider for its models; keep the ones you need and the default model, then Save.
  4. On the row, Test checks the key, Replace the key sets a new one, Delete asks for a second click (Confirm deletion) and erases the key.

The provider becomes the fl:<name> engine: its models join every text model list (the Vectorlab AI dialog, the roles above). The key goes to the vault and is never shown again.

Connect several local servers

  1. Under Local LLM (Ollama), the Local servers list starts with your Ollama, set just above.
  2. + Add a server: pick a preset (Ollama, LM Studio, llama.cpp, vLLM); the URL must be on this PC or on your local network.
  3. Read the models fills the list, pick the default model, then Save.
  4. Test says whether the server answers and how many models it publishes.

Each server becomes the local:<name> engine, free, in the same lists as free providers.

Protect your keys in the vault

  1. Open Settings › Vault.
  2. Choose a master password (at least 8 characters), type it twice, then Set up vault. Your keys are encrypted and leave the plain-text file.
  3. Close removes the keys from memory: nothing paid can go out. Open makes them active again with the password.
  4. Remember on this PC opens the vault on its own at launch, for your Windows session; Stop remembering asks for the password again.

On each row of API keys, a badge tells where the key lives: in the file, in the vault, or vault closed (one click takes you there).

Good to know

The vault password is stored nowhere: if lost, it cannot be recovered. Write it down, or keep an encrypted archive.

Export archive creates a .dzk file that carries your keys, caps and rates to another PC or your phone, protected by its own password. Import an archive… takes them back.

Settings › Diagnostics shows the status of all keys at once (never their value) and the providers' balances. Each row carries Set up, which opens the section where the key is set.
