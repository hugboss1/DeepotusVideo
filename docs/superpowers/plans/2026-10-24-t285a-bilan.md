## Décisions prises en cours d'exécution (à vérifier)

- ecrire_dossier crée le dossier au premier appel avec slug = slugify(titre de la conversation) ou « campagne » ; agent_store garde le chemin dans `dossier` — l'interface dossier_campagne(espace, slug) reste — coût si faux : un nom de dossier à renommer.
- le dépôt (T7) s'écrit par une aide de T5 `enregistrer_depot(cid, nom, texte) -> str` (fichier sous le dossier de la conversation, `depots/`), et `lire_document(depot=nom|url=…)` le relit — T5 la définit, T7 l'appelle — coût si faux : une aide à déplacer.
- la route message (T7) vérifie `moteurs_texte.configure("anthropic")` AVANT d'appeler tour() ; tour() n'écrit le message utilisateur qu'après le premier verifier réussi — coût si faux : un message orphelin en base.
- l'id de l'espace du jeton est relu dans espaces (défauts) par l'implémenteur de T6 ; à défaut, le marqueur crypto de la persona — coût si faux : consignes crypto absentes sur l'espace du jeton (banc dédié).
- deviser_generation couvre image (op image du modèle), video (pricing.video_request_op), voix (op tts existante) en relisant les ops que les routes utilisent ; un genre inconnu → ok=False — coût si faux : un devis faux sur un genre.
- un changement d'état de carte ne mute JAMAIS le message d'origine : il s'écrit comme un message neuf (role outil/fait, bloc carte de même `n`) ; l'import (T2) traite donc « même id, empreinte différente » comme un conflit sans écraser — coût si faux : une acceptation de carte faite au téléphone apparaîtrait comme conflit au PC.
- les mutations des tâches T1-T6 se font en bloc à l'étape mutations de T7 (le plan les y liste explicitement), plus une mutation par garde critique — coût si faux : un défaut de T1-T6 vu plus tard, mais avant la PR.
- les 8 gabarits d'erreur d'agent_store (dette de T2) sont traduits dans le tour de correctif de T4 — coût si faux : aucun, c'est un rouge introduit par la branche.
- le devis par message doit chiffrer le VRAI modèle : la grille gagne un prix par modèle Claude (repli : prix du fournisseur), dans T4 — c'est aussi le point 8 du §9 de la spec mobile — coût si faux : un devis sous-estimé ×4 à ×20 pour Sonnet/Opus.
- Haiku au prix public (1/5 $/Mtok) quand le modèle est donné ; l'ancien 0,80/4,00 reste sans modèle — coût si faux : un devis Haiku un peu plus haut que l'ancien, jamais plus bas que le réel.
- la spec §5 veut que les routes de génération rangent le rendu dans l'espace de la campagne (« t285a l'ajoute ») mais aucune tâche du plan ne le porte : T7 l'ajoute aux trois routes que deviser_generation vise (image, vidéo, voix) — `espace_id` facultatif du corps → JobRecord.espace_id et plafonds.verifier(espace_id=…), sans lui comportement inchangé — coût si faux : rendus de campagne rangés dans l'espace actif.
- mots interdits = persona de l'espace + brief actif (global) : plus strict que le mode rapide, accepté (refus = réécriture, jamais une publication) — coût si faux : quelques refus de trop.
- l'espace du jeton est « deepotus » (persona « Deepotus — Solana Memecoin », aucun « deepotus-jeton » n'existe), plus le marqueur crypto de la persona — si DeepotusVideoGen partage cet espace, ses campagnes reçoivent aussi les consignes crypto (plus strict, sans risque) — coût si faux : consignes crypto en trop sur l'app.
- T7 pilote tour() sous contextlib.aclosing (verrou libéré même si le client SSE coupe), avec un banc d'arrêt anticipé qui vérifie _VERROUS vide — coût si faux : une conversation bloquée « occupée » jusqu'au ramasse-miettes.
- un devis image/voix accepté reçoit son fait tout de suite : la réponse de carte porte `fichier` (nom validé, présent dans le magasin) — le chemin vidéo garde job_id → fait au GET — coût si faux : l'écran T8 doit transmettre le nom du fichier produit.
