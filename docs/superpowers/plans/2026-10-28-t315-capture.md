## Relevé (28/10)

- **Navigateur réellement lancé.** `scripts/launch-silent.vbs` de l'installation (lu, non modifié) ouvre
  `http://deepotus.localhost:8765` par `shell.Run urlApp` : le navigateur **par défaut**. Registre :
  `UrlAssociations\http(s)\UserChoice = ChromeHTML` → **Google Chrome 156.0.8078.48** (Edge 156.0.4314.50 installé
  mais pas par défaut). Element Capture (`RestrictionTarget.fromElement`, `track.restrictTo`) est livré depuis
  Chrome 132, `preferCurrentTab` depuis Chrome 94, Capture Handle depuis 102, MediaRecorder MP4/H.264 depuis 126 :
  tout est présent sur le navigateur lancé. **Repli propre** quand une API manque : Element Capture absent ou refusé →
  tout l'onglet, dit à l'écran (« Element Capture indisponible : tout l'onglet est filmé ») ; `getDisplayMedia`
  absent → bouton grisé avec la raison ; MP4 absent → WebM (VP9 puis VP8).
- **Chargement sans maillon pour l'écran.** Comme `dz-pour-qui.js` (t309), l'enregistreur vit dans des modules
  `frontend/shared/dz-capture*.js` chargés par `frontend/dist/index.html`. Un seul maillon de bundle, `dzcapture`, pour
  marquer les écrans secrets de Réglages (le bundle n'a aucun repère DOM pour la section affichée).
- **Écrans secrets.** Réglages : sections `coffre`, `appareils` (appairage, QR), `keys` (clés d'API et leurs aperçus
  masqués), `accounts` (identifiants OAuth), `transfert` (mots de passe d'archive) : `div.scroll` du panneau de droite
  (`s==="accounts"&&…`). Champs `type=password` : 2 dans le bundle, 3 sites `dzSlSaisie/dzFlSaisie(…,"password")`,
  `dz-espace-assistant.js` (secret des comptes), `dz-prospects.js` (clé de recherche).
- **Identité d'un clic.** `agent_aide.rapprocher([{t, i}], ecran)` reconnaît un élément visible par son libellé ou
  son infobulle (FR/EN) et rend sa fiche du catalogue : on le réutilise côté serveur, le navigateur n'envoie que
  `{t, i}` (même relevé que `releverVisibles` : jamais la valeur d'un champ).
- **Bibliothèque.** Une vidéo entre dans la Bibliothèque comme un job fini (`routes._sfx_video_job`, patron de
  `/videos/upload`) ; `provider="capture"` entre dans `_JOBS_SANS_DEPENSE` (sinon facturé comme Seedance) ; source
  d'index `capture` (`library_index.SOURCES`, propre).

## Décisions

1. **Cadre** (spec §8.1). `getDisplayMedia({video:{frameRate:30}, audio:false, preferCurrentTab:true,
   selfBrowserSurface:"include", surfaceSwitching:"exclude", monitorTypeSurfaces:"exclude"})`. Refus si
   `displaySurface !== "browser"` (jamais le bureau ni une fenêtre). Onglet vérifié par **Capture Handle**
   (`setCaptureHandleConfig` avec un jeton aléatoire, relu par `track.getCaptureHandle()`) : un autre onglet est refusé.
   Mode **« app »** (défaut) : Element Capture sur `#root` (posé `isolation:isolate` le temps de la capture). Mode
   **« onglet »** : tout l'onglet. Choix de prudence noté : en mode « app », les boîtes posées hors de `#root`
   (dialogues partagés, tiroir F1, portails React vers `body`) ne sont pas filmées ; l'écran le dit et propose « Tout
   l'onglet ».
2. **Voix** : `getUserMedia({audio:{noiseSuppression, echoCancellation, autoGainControl}})`, jauge par AnalyserNode.
   **Caméra** : éteinte par défaut ; la case « J'accepte d'allumer ma caméra » est l'accord (geste visible) ; encart
   flottant DOM hors `#root` (déplaçable, redimensionnable, forme cercle | carré | coins vifs) dont la place pilote le
   compositeur ; **témoin** « Caméra allumée » dans la pastille tant que la piste vit. Aucune piste n'est ouverte
   avant « Démarrer ».
3. **Piste des clics** (`.dzclics.json`, version 1) : `pointerdown` en capture sur la fenêtre et les cadres de même
   origine ; jamais `keydown`/`input`/`value`. Un clic : `{type:"clic", t, x, y, bouton, ecran, cible:{balise, role,
   t, i}}` ; `x, y` normalisés 0..1 dans le cadre filmé. Un clic dans une zone secrète : `secret:true`, sans `t`/`i`.
   Changements d'écran (`localStorage.dz_view` relu toutes les 500 ms) : `{type:"ecran", t, ecran}`. Débuts et fins de
   génération : ajoutés par le SERVEUR à la fin, d'après les jobs créés pendant la fenêtre de capture. Le serveur
   relit tout (liste blanche des champs, textes ≤ 40/80, aucun chemin ni nom de fichier, caractères de contrôle ôtés,
   20 000 événements au plus) et pose `fiche` (id du catalogue) par `agent_aide.rapprocher`.
4. **Masquage** (spec §8.2). Sélecteur unique `SELECTEURS_SECRETS = '[data-dz-secret], input[type="password"]'`.
   Pendant une capture (`html[data-dz-capture]`) : flou CSS 16 px + `pointer-events` gardés sur les éléments, CACHE
   opaque « Masqué pendant l'enregistrement » sur les écrans (`data-dz-secret="ecran"`) ; la feuille est aussi posée
   dans les cadres de même origine. Le compositeur peint en plus un cache opaque sur chaque rectangle secret, à chaque
   image (défense en profondeur) ; la piste brute « écran » ne voit que le flou DOM. Le maillon `dzcapture` pose
   `data-dz-secret="ecran"` sur le panneau de Réglages pour coffre, appareils, keys, accounts, transfert.
5. **Compositeur commun** (spec §8.3) : `creerScene()` dans `dz-capture-scene.js` ; des CALQUES triés par `z`
   (`{id, z, dessiner(ctx, ctxScene)}`), sources nommées (`ecran`, `camera`), `flux(fps)` = `canvas.captureStream`.
   Calques de départ : écran (100, avec zoom en direct désactivable), caviardage (900, toujours au-dessus des calques
   < 900), effets de clic (500), encart caméra (600). L'horloge est un `setInterval` (pas `requestAnimationFrame`).
6. **Pistes** : `scene` (canvas + voix mixée), `ecran`, `camera`, `voix` ; une MediaRecorder par piste, morceaux
   d'une seconde envoyés DANS L'ORDRE (`PUT /api/capture/sessions/{id}/pistes/{piste}/{n}`), MP4 si le navigateur le
   donne, sinon WebM. Fin : `POST …/terminer` (piste des clics, durée) → la scène entre dans la Bibliothèque (job
   `capture`, index `capture`), les pistes brutes restent dans `DATA_ROOT/captures/<id>/`.
7. **Pastille** : flottante (haut, centre), hors `#root`, « ● REC mm:ss », icônes micro/caméra, bouton « Arrêter »
   toujours accessible ; l'arrêt du partage par le navigateur arrête proprement.
8. **Drapeau de preuve** : `localStorage.dz_capture_preuve = "1"` remplace écran (esquisse DOM → canvas), caméra
   (canvas animé) et voix (oscillateur) par des flux factices ; jamais posé par le code ; dit dans la pastille
   (« preuve »).

## Contrat pour t316-t319

Tout passe par `window.__dzCapture` (posé par `dz-capture.js`) et par les modules ES importables
`/shared/dz-capture-scene.js` et `/shared/dz-capture-logique.js`.

- **Scène (t316 skins, t318 live).** `import { creerScene } from "/shared/dz-capture-scene.js"`.
  `creerScene({largeur, hauteur, fps=30, horloge?}) -> scene` :
  - `scene.canvas` (HTMLCanvasElement), `scene.largeur`, `scene.hauteur` ;
  - `scene.source(nom, video|null)` : branche une source (`"ecran"`, `"camera"`, ou toute autre) ;
  - `scene.ajouterCalque({id, z, dessiner(ctx, s)})` / `retirerCalque(id)` / `calques()` : un calque est une
    fonction de dessin appelée à chaque image, triée par `z` croissant ; `s = {t, largeur, hauteur, sources, etat}`.
    Un skin pose ses calques entre 100 (écran) et 900 (caviardage) : cadre/fond < 100, bandeau, logo, minuteur,
    chapitre 700-800. **Rien ne se dessine au-dessus du caviardage (z ≥ 900)** : `ajouterCalque` refuse un `z` ≥ 900
    sauf l'id réservé `caviardage`.
  - `scene.etat` : objet partagé (`encart: {x, y, l, h, forme}` normalisés 0..1, `zoom`, `clics`, `secrets`), lu par
    les calques ; un skin y change `encart.forme`, `encart.bord`, `encart.ombre`.
  - `scene.flux(fps)` → MediaStream (une seule fois par scène) ; **le live (t318) encode CE flux** (plus la voix
    mixée `__dzCapture.session().audio`), jamais une autre composition.
  - `scene.demarrer()` / `scene.arreter()` / `scene.dessiner(t)` (une image à la demande, pour l'aperçu d'un skin).
- **Session en cours.** `window.__dzCapture.session()` → `null` ou `{id, scene, debut, pistes, options, audio,
  clics: PisteClics}`. Événements DOM sur `window` : `dz-capture:debut` `{id}`, `dz-capture:clic` `{evt}`,
  `dz-capture:ecran` `{ecran}`, `dz-capture:fin` `{id, capture, job_id}`. t318 réutilise `ouvrir(options)` /
  `arreter()` et ajoute ses propres sorties à la scène.
- **Piste des clics (t317 montage, t319 tutoriels).** Fichier `DATA_ROOT/captures/<id>/<id>.dzclics.json` :
  `{version:1, id, debut_utc, duree_ms, cadre:{largeur, hauteur, mode:"app"|"onglet"}, evenements:[…]}`, triés par
  `t` (ms depuis le début). Types : `clic` `{t, x, y, bouton, ecran, secret?, cible:{balise, role, t, i},
  fiche: id|null}`, `ecran` `{t, ecran}`, `generation_debut` / `generation_fin` `{t, job_id, provider, statut?}`.
  Jamais de touche, de valeur saisie, de chemin ni de nom de fichier. Lecture : `GET /api/capture/sessions/{id}`
  (session + piste) ; pistes brutes : `GET /api/capture/sessions/{id}/pistes/{scene|ecran|camera|voix}`.
- **Masquage.** `SELECTEURS_SECRETS` et `CSS_MASQUE` (dz-capture-logique.js) sont la seule définition ; tout écran
  neuf qui montre un secret pose `data-dz-secret` (`"ecran"` pour un écran entier). `test_capture_secrets.py` le garde.
