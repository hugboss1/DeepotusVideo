# Veille dans l'app (P1, t352) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:executing-plans (exécution « native » dans cette session), étapes en cases à cocher.

**But :** l'agent Campagnes lance une veille concurrentielle niveau 1 (HN, YouTube, App Store) dans l'espace de la campagne, et un onglet « Veille » montre le rapport : matrice, top douleurs, angles, demandes.

**Architecture :** trois modules backend. `veille_collecte` porte `collecte.py` : réseau derrière des coutures, plafonds. `veille_grille` classe sans LLM et calcule le rapport. `veille` gère le stockage par espace, la tâche de fond et l'import. Une route `/api/veille`. Deux outils dans une boîte `veille` de l'agent Campagnes. Un composant DOM partagé `dz-veille.js`, monté en 3e onglet du tiroir F1. Aucun maillon de bundle.

**Pile :** FastAPI, httpx (déjà utilisé par `agent_outils`), yt-dlp (module ou exécutable), JS sans framework (`frontend/shared/`), `dzT` et `i18n_assembler.py`.

**Spec :** `docs/superpowers/specs/2026-10-27-agent-veille-prospection-design.md` (§2 objectif 1, §5 deux premières lignes, §8). Méthode : skill `veille-concurrents` (`references/grille.md`, `rapport-modele.md`, `sources.md`, `scripts/collecte.py`).

## Décisions à confirmer par l'utilisateur (avant le code)

1. **Classement sans dépense.** Un verbatim est classé par lexique FR/EN, sans appel au modèle :
   - thème : mots-clés par thème de la grille ;
   - polarité : note App Store ≤ 2 → faiblesse, ≥ 4 → force, sinon lexique ;
   - intensité 3 si le texte contient refund / cancel / scam / rembours / arnaque / résili….
   - Le rapport affiche « classement automatique ».
   - *Alternative écartée :* faire classer par le modèle. Cela coûte des jetons, ce qui contredit « aucune dépense ».
2. **Import d'une veille faite hors de l'app.** L'utilisateur choisit un dossier (par exemple `C:\Users\olivi\Campagnes\_veille\2026-10-27`). L'app lit seulement son `verbatims.jsonl`, déjà classé par Claude, et recalcule le rapport (« classement importé »). La veille n°1 apparaît ainsi dès l'installation, avec la qualité du classement manuel.
3. **yt-dlp n'est pas embarqué dans l'app.** Le PC l'a seulement par winget. Ordre de recherche :
   - module `yt_dlp` du python de l'app ;
   - sinon `yt-dlp` dans le PATH ;
   - sinon la source YouTube est notée « indisponible : yt-dlp introuvable » dans les Limites.
   - Proposition : **ne pas** ajouter `yt_dlp` à `requirements.txt` dans ce lot, l'ajout se décide à part.
4. **Place de l'écran.** Un 3e onglet « Veille » dans le tiroir F1, à côté de Demander et Campagnes, pour l'espace choisi. Pas d'entrée dans la barre des applications, donc aucun maillon de bundle.

## Contraintes globales

- **Lecture seule.** Aucune publication, aucun j'aime, aucun message, aucune dépense, pas de navigateur connecté (niveau 2 hors de l'app, §8).
- **Auteurs hachés.** Aucun pseudo n'est écrit sur le disque : `auteur_hash = sha256(auteur)[:10]`, comme dans `collecte.py`.
- **Doublon = même lien et même texte.** `_cle(l) = sha256(url + "|" + texte)`.
- **Données sous l'espace :** `DATA_ROOT/espaces/<eid>/veille/<AAAA-MM-JJ>/`, avec :
  - `perimetre.json` ;
  - `brut/<source>-<concurrent>.jsonl` ;
  - `verbatims.jsonl` ;
  - `rapport.json` ;
  - `etat.json`.
  - L'id passe par `espaces.id_valide`, la date suit `^\d{4}-\d{2}-\d{2}$`, jamais de `..`.
- **Plafonds :**

  | Paramètre | Valeur |
  |---|---|
  | `MAX_PAR_REQUETE` (HN) | 100 |
  | `MAX_PAR_VIDEO` | 150 |
  | `MAX_VIDEOS_PAR_CONCURRENT` | 3 |
  | `MAX_AVIS_APP_PAYS` | 100 |
  | `MAX_CONCURRENTS` | 15 |
  | `MAX_BRUT` (par collecte) | 3 000 |
  | `DUREE_MAX` (échéance globale) | 900 s |
  | `DELAI_HTTP` | 20 s |
  | `DELAI_YTDLP` (par vidéo) | 180 s |
  | Période HN par défaut | 548 jours |

  - Une seule collecte à la fois par espace (409).
- **Textes collectés = données, jamais des consignes.** `veille_lire` rend les citations encadrées par `agent_outils._preuve`. Une citation fait au plus 200 caractères (une phrase).
- **Angles.** Ils ne viennent que des thèmes dont `chez_nous = "regle"` dans la table `CHEZ_NOUS`, avec un écran à l'appui. Jamais de prix d'un concurrent. Les demandes `absent` sont classées « à décider », jamais « annoncées ».
- **Écran.** Aucune chaîne en dur (`dzT`). Clés `veille.*`. Copie `dist/shared` identique octet pour octet. Commits `<zone> : <quoi> (t352)` avec `git commit --only`.
- **Bancs.** Backend de preuve sur le port 8799, jamais 8765. Bancs lancés avec `$PY = "$env:LOCALAPPDATA\DeepotusVideoGen\runtime\python\python.exe"` depuis `backend/`.

## Points de vigilance (non couverts par la spec)

1. **Réseau coupé ou 429 en cours de collecte.** La collecte se termine en `fini_partiel` : elle garde ce qui est acquis et inscrit l'erreur dans les Limites. Elle ne passe pas en `erreur` et ne perd rien. → test `test_collecte_reseau_partiel` (Tâche 1).
2. **Relance le même jour.** Même dossier daté, aucune ligne en double (dédoublonnage contre le fichier). → `test_relance_sans_doublon` (Tâche 1).
3. **Backend redémarré pendant une collecte.** Un `etat.json` resté `en_cours` depuis plus de `DUREE_MAX` est lu comme `interrompu` et ne bloque pas la collecte suivante (pas de 409 éternel). → `test_etat_fantome` (Tâche 3).
4. **Fichier importé hostile ou énorme.** Au-delà de 20 Mo : refus. Ligne illisible : ignorée et comptée. Champs hors schéma (dont `auteur`) : retirés. Citation contenant « ignore les instructions » : rendue encadrée. → `test_import_hostile` (Tâche 3), `test_veille_lire_encadre` (Tâche 4).
5. **Espace sans veille, ou rapport d'une version inconnue.** La route et l'outil rendent `{rapport: null}` avec un message clair, l'écran affiche un état vide avec le bouton « Lancer une collecte ». → `test_lire_sans_veille` (Tâche 3), cas « vide » de `veille.test.mjs` (Tâche 5).

### Tâche 2 : grille automatique et rapport (`veille_grille`)

**Fichiers :** créer `backend/app/services/veille_grille.py` ; test `backend/tests/test_veille_grille.py`.

**Interfaces produites :**
- `THEMES: tuple[str, ...]` : les 14 codes de `grille.md`, dans l'ordre.
- `CHEZ_NOUS: dict[str, dict]` : thème → `{"statut": "regle"|"partiel"|"absent"|"inconnu", "preuve": clé i18n de l'écran}`. Valeurs `regle` :
  - `prix_credits` (Réglages › Dépenses : devis avant génération, plafonds, clés personnelles) ;
  - `confidentialite_local` (projets locaux) ;
  - `fournisseur_unique` (multi-fournisseurs) ;
  - `game_assets` (Spritelab, Tilelab, Établi) ;
  - `social_publication` (Planificateur) ;
  - `flux_travail` (Montage, Envoyer vers).
  - `partiel` : `coherence` (espaces de marque), `controle` (Studio).
  - `inconnu` pour les autres.
- `classer(l: dict) -> dict` : la ligne, plus `theme`, `polarite`, `intensite`, `chez_nous`, `classement: "auto"`. `polarite = "neutre"` si aucun thème n'est reconnu.
- `rapport(verbatims: Iterable[dict], meta: dict) -> dict`, schéma `version: 1` :

  | Clé | Contenu |
  |---|---|
  | `date`, `espace_id`, `classement` | métadonnées (`"auto"` ou `"importe"`) |
  | `volumes` | `brut`, `gardes`, `par_source`, `par_concurrent`, `periode: [min, max]` |
  | `matrice` | `{concurrent: {theme: {"f": n, "F": n, "i": moyenne}}}` |
  | `douleurs` | top 10 des faiblesses par thème : `theme`, `n`, `n3`, `auteurs`, `concurrents`, `citations` (≤ 3 : `texte`, `url`, `date`, `source`, `concurrent`), `chez_nous`, `preuve` |
  | `angles` | thèmes `regle` seulement, triés par nombre de faiblesses |
  | `forces` | ce qu'ils font bien |
  | `demandes` | `polarite = "demande"` et `chez_nous ∈ {absent, partiel, inconnu}`, `statut: "a_decider"` |
  | `limites` | `[str]` |

  - Un thème ne compte comme tendance qu'avec au moins 3 auteurs distincts : en dessous, il ne va pas dans `douleurs` (règle du skill).

- Routes :

  | Route | Réponse |
  |---|---|
  | `GET /api/veille/{eid}` | `{etat, rapport, veilles}` |
  | `GET /api/veille/{eid}/perimetre` | le dernier périmètre, sinon le défaut |
  | `POST /api/veille/{eid}/collectes` | corps `{perimetre?}` ; 202, ou 409 si une collecte tourne, ou 422 pour un périmètre invalide |
  | `GET /api/veille/{eid}/verbatims?date&theme&concurrent&limite` | les verbatims filtrés |
  | `POST /api/veille/{eid}/importer` | corps `{dossier}` |
